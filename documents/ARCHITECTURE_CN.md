## 分层架构

### 1. 表现层 (Controller)

**职责**：
- 接收 HTTP 请求
- 参数校验
- 调用 Service 层
- 返回统一响应格式

**主要 Controller**：
- `AuthController` - 用户认证
- `SeckillActivityController` - 活动管理
- `SeckillController` - 秒杀核心逻辑
- `OrderController` - 订单查询

### 2. 业务层 (Service)

**职责**：
- 业务逻辑处理
- 事务管理
- 异常处理

**主要 Service**：
- `ISeckillService` - 秒杀业务逻辑
- `ISeckillActivityService` - 活动业务逻辑
- `ISeckillOrderService` - 订单业务逻辑

### 3. 数据访问层 (Mapper)

**职责**：
- 数据库操作
- SQL 执行

**技术**：MyBatis-Plus（简化 CRUD）

### 4. 缓存层

#### Redis 缓存
- **库存缓存**：`seckill:stock:{activityId}`
- **活动缓存**：`seckill:activity:{activityId}`
- **成功用户**：`seckill:success_users:{activityId}` (Set)
- **分布式锁**：`seckill:task:lock`

#### 本地缓存
- **内存标记**：`Map<Long, Boolean> localOverMap`
- 商品售罄后直接拦截，减少 Redis 查询

### 5. 消息队列 (RabbitMQ)

**队列配置**：
- Exchange: `seckill.exchange`
- Queue: `seckill.queue`
- Routing Key: `seckill.message`

**消息格式**：
```json
{
  "userId": 1001,
  "activityId": 1
}
```

**消费者**：
- 10个并发消费者
- 异步处理订单创建
- 保护数据库

## 核心优化点

### 1. 防超卖机制

**三层防护**：

1. **Redis 层**：Lua 脚本原子操作
   ```lua
   -- 检查用户是否已购买
   -- 检查库存是否充足
   -- 扣减库存
   -- 记录成功用户
   ```

2. **数据库层**：
   - 唯一索引：`(user_id, activity_id)` 防止重复购买
   - 乐观锁：`UPDATE ... SET stock = stock - 1 WHERE stock > 0`

3. **应用层**：
   - 本地缓存标记，商品售罄后直接拦截

### 2. 性能优化

**缓存策略**：
- Redis 预减库存（秒杀开始前预热）
- 本地内存标记（JVM 级别）
- 活动信息缓存（减少数据库查询）

**异步处理**：
- RabbitMQ 削峰填谷
- 10个并发消费者
- 数据库写入异步化

**连接池优化**：
- Redis 连接池：max-active=100
- MySQL 连接池：maximum-pool-size=20
- RabbitMQ 消费者：concurrency=10

### 3. 安全防护

**接口保护**：
- 秒杀路径隐藏（动态生成 Path + Token）
- 图形验证码防刷
- 访问频率限制（5秒内最多5次）
- JWT Token 认证

## 数据流

### 秒杀请求处理流程

```
1. 用户请求
   ↓
2. 认证拦截器（验证Token）
   ↓
3. 限流拦截器（检查访问频率）
   ↓
4. Controller 接收请求
   ↓
5. Service 业务处理
   ├─ 检查本地缓存标记
   ├─ Redis Lua 脚本扣减库存
   └─ 发送消息到 RabbitMQ
   ↓
6. 返回"排队中"
   ↓
7. RabbitMQ 消费者异步处理
   ├─ 从队列获取消息
   ├─ 查询活动信息
   ├─ 创建订单（MySQL）
   └─ 更新库存（MySQL）
```
